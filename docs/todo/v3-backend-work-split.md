# 해미 v3.0 백엔드 작업 분담서

> 기준: 기능명세서 v3.0 통합판 · 코드베이스 실측(2026-08-02)
> 대상: 백엔드 개발자 2명 (실력 동등 가정)

---

## 1. 현황 진단

패키지는 `auth`, `m1`~`m5`로 구성. **명세는 v3.0인데 코드는 v2.0 구현 상태**로, 신규 구축(M0)과 대규모 리팩터링(M1~M5)이 병존한다.

### 핵심 갭

- **M0 모듈 전체 부재** (`m0` 패키지 없음)
  - `Elder`, `FamilyGroup`, `Person`(생존/노출), `ElderStatus`, `EventLog`, `AccessMode`, `LifeStory`, `SensitiveTopic` 미존재
  - `auth.Member`에 role만 있고 가족 그룹 / 어르신 프로필 개념 없음
- **M3**: `correctAnswer`, `isCorrect()`, `WrongAnswerPattern`, `GrandchildChance`(실시간 소진형) → v3.0 폐기·재설계 대상
- **M2**: `FamilyRanking`, `BadgeGrade`, `RankingController` → v3.0 랭킹 전면 폐기
- **M1**: `QuizItem`, `Album`(앨범/추억글 분리) → v3.0 `memory` 통합·퀴즈 폐기
- **M4**: `CognitiveReport`, `CognitiveChangeAlert`(인지 점수 중심) → v3.0 회상 기록 중심 개정
- **M5**: `WalkRoutine`(산책) → v3.0 보류
- **횡단 부재**: 발화 감지(VAD) 0건, 선다운로드/오프라인 완주 0건, 콘텐츠 안전검증(사별 인물 현재형 차단) 0건

## 6. 공유·조율 지점 (공동 합의 후 착수)

1. **도메인 경계**: A의 `Elder` / `Person`을 B의 세션·알림이 참조 → Phase 1 첫 주에 **엔티티 인터페이스(ID·상태·노출 조회 API) 계약 먼저 확정**
2. **배치 스케줄러** (명세 3.4): 08:00 A(콘텐츠) → 08:45 B(선다운로드) → 09:00 B(알림) 순서 의존. 스케줄러 프레임 공동 설계
3. **S1 회귀 테스트 스위트** (부록 A, 20건): 릴리스 게이트. 각자 담당분 작성하되 CI 게이트는 공동 소유
